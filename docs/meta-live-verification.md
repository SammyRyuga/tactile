## Incident and API contract

At revision `38b6d30`, the “selected model is unavailable” error could mean either that the catalog returned HTTP 404 or that a successful list omitted the selected ID. The Settings response for request `014e92a2-cfb9-4c19-87bd-b5473385c27b` did not distinguish them. The production upstream response for that request is unavailable, so account access for the rotated key remains unknown.

Ryan’s [catalog fallback](https://github.com/SammyRyuga/tactile/pull/35) keeps the Bearer-authenticated list request and uses the documented single-model lookup when the list is missing, malformed, or omits the exact ID. Meta documents `object: "list"`, `data[].id`, and a single-model object with the exact `id`. The list documents a `client` option and no pagination cursor. Tactile uses `muse-spark-1.3`, `muse-ember-1.0`, and `muse-wonder-1.0`. Meta’s public catalog does not establish team access, generation, or billing for a particular key. [List models](https://dev.meta.ai/docs/api-reference/models/list-models) · [Retrieve a model](https://dev.meta.ai/docs/api-reference/models/retrieve-model) · [Authentication](https://dev.meta.ai/docs/authentication) · [Model catalog](https://dev.meta.ai/docs/models)

Ordinary Settings saves use metadata only. The explicit model test rechecks the metadata and sends at most one short Responses request if the result is still inconclusive. A documented `404/model_not_found`, invalid key, permission denial, billing failure, rate limit, or provider outage stops validation. An unrecognized 404 from the generation endpoint is reported separately. Tactile keeps the provider status and a safe category for diagnosis. [Meta errors](https://dev.meta.ai/docs/error-handling) · [Responses](https://dev.meta.ai/docs/protocols/responses)

Tactile launches the pinned Python worker at startup to confirm review imports with a bounded local handshake. `/health` reports the web service and release revision. When signed in, `GET /api/status` also reports `workerReady`. The handshake uses no provider. The authorized database needs both quota migrations for live extraction and review. See [deployment verification](DUAL_DEPLOYMENT.md#verify-a-deployment).
