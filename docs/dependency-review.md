## Development lint advisory ([Issue #13](https://github.com/SammyRyuga/tactile/issues/13))

[GHSA-g3hv-75wg-m249 / CVE-2026-118764](https://github.com/advisories/GHSA-g3hv-75wg-m249) affects minimatch versions 7.0.0 through 11.0.0. The first patched release is 11.0.1. On Tactile revision `abe457d`, the full audit reported two moderate entries for the same dependency chain: `eslint@10.8.1 → minimatch@10.2.6`. The other copies under `@eslint/config-array` and `@typescript-eslint/typescript-estree` already resolved to 11.0.9. The production audit reported zero vulnerabilities.

The advisory requires an attacker-controlled glob pattern processed at optimization level 2 or higher. Tactile runs `eslint .` locally and in CI with checked-in ignore patterns. The reviewed ESLint entry points for the affected copy passed `dot: true` and inherited minimatch’s default optimization level of 1. A matching input path was not found in the ordinary lint workflow. The vulnerable package was present in the development install, where other callers or changed configuration could expose it.

Pinned ESLint to 10.15.0, the [upstream release that requires a patched minimatch](https://github.com/eslint/eslint/releases/tag/v10.15.0). All three consumers now share minimatch 11.0.9. The lockfile changes are confined to development dependencies, including ESLint’s new cache dependencies. The existing TypeScript 5.9.3 and typescript-eslint 8.73.0 versions satisfy the updated lint toolchain.
